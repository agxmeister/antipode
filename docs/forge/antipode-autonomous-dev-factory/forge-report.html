Antipode

Autonomous downstream software factory for a single project owner

Outcome: Hardened. The idea survived with its mechanism rewritten. The product is the acceptance surface, not the agents.

What the idea became

A problem does not go in; structured tasks with acceptance criteria go in. Ephemeral, role-specific Claude agents work each task on its own branch, produce a mandatory evidence artifact and a live preview, and the owner accepts or corrects from Telegram in about a minute. Accept triggers rebase, revalidation, merge and prod deploy. A non-intelligent coordinator keeps the ledger; intelligence appears only as stages.

Locked decisions

  • Downstream only for MVP; upstream idea-forming is phase two.
  • Single owner is the only reviewer; first user is the author.
  • Task contract in the repo: goal, acceptance criteria, required evidence, dependencies. Intake agent asks for missing criteria. SDD-friendly means consuming specs, not inventing them.
  • Branch per task. Shared workspace means shared repo and visibility, never simultaneous edits.
  • Roles as config (instructions, skills, MCPs): intake, implementer, validator, evidence producer, triage. Each runs in a fresh container with its own context from task record and repo. Worker never grades its own work.
  • Coordinator is dumb and persisted: state, triggers, timeouts, retries, iteration budget. No central LLM. Triage agent decides re-run vs. park in a deferred-work ledger.
  • Evidence before review: before/after screenshots for UI, counts/checksums/requests/tests for data and backend. Parking lot shown at review.
  • Review is of the running result, minimum text, maximum visualization, via Telegram.
  • Correction is feedback on the same task and branch; no new intake; report leads with the diff vs. what the owner saw.
  • Accept is not merge: rebase, revalidate, merge, deploy. Dependents start only after merge. No stacked branches.
  • Demo-first is enforced: a working preview environment is the first task of any project. Project recipe in repo; ephemeral seeded DB per preview; no prod snapshots.
  • Ephemeral agent containers; previews sleep when idle. Subscription billing in MVP; per-task, per-stage cost tracking is essential.
  • MVP runtime: Podman on one box, Telegram only, Claude only.

Rejected, and why

  • Simultaneous edits to one shared tree — in-progress intents collide; no lock or CRDT fixes that. Replaced by branch per task.
  • Orchestrator agent — nondeterministic, loses the plot on restart. Replaced by a persisted coordinator plus triage stage.
  • Agent writes its own exam — evidence defined by the task before work, not by the worker after.
  • Web UI, multi-vendor agents, cluster or cloud, automated reviewer — phase two; each has a plug left in the design.
  • Stacked branches and batched deploys — slower and sane wins for one owner.

Weak points that survived

  • One human's review throughput is the real ceiling. Acceptance must stay near one minute or the factory just grows a queue.
  • Subscription spend is not metered in money. Cost tracking rests on tokens, session time and rate-window usage, and is approximate.
  • Preview environments are a quarter of work per team at real companies; the recipe pushes that cost onto the owner.
  • The triage agent can loop; the iteration budget is the only brake.
